# 근태 연동 설계

## 목적

이 시스템의 인력 수는 계획상 정원이 아니라 **해당 일자에 실제 출근해 작업 가능한 인원**이다.
출입 카드, 모바일 출근, ERP/HR 근태 시스템에서 온 이벤트를 표준 근태 스냅샷으로 바꾼 뒤,
그 결과만 GA 입력으로 사용한다.

```text
[사원증/모바일 태그] → [사내 근태·HR 시스템] → [근태 어댑터]
                                                   ↓
                               attendance.csv / Attendance API 응답
                                                   ↓
                         가용 인력 풀 + 지각 투입 가능 시각
                                                   ↓
                         GA 재최적화 → 작업지시표 · 간트차트
```

## 데이터 계약

근태 어댑터가 받거나 생성하는 최소 컬럼은 아래와 같다.

| 컬럼 | 예시 | 의미 |
|---|---|---|
| `worker_id` | `W014` | HR 사번과 매핑된 작업자 ID |
| `work_date` | `2026-03-02` | 작업일 |
| `status` | `출근`, `지각`, `미출근`, `휴가`, `교육`, `타공정` | 현재 근태/가용 상태 |
| `check_in_time` | `08:30` | 마지막 유효 출근 태그 시각 |
| `available_from_min` | `30` | 08:00 기준 GA 투입 가능 시각(분) |
| `available_until_min` | `720` | 당일 투입 종료 시각(분) |
| `source` | `HR_ATTENDANCE_API` | 이벤트 출처와 추적 정보 |

- `출근`, `지각`만 가용 인력 풀에 들어간다.
- `지각`은 풀에 포함되지만 `available_from_min` 전에는 편성되지 않는다.
- `미출근`, `휴가`, `교육`, `타공정`은 GA의 `workers` 입력에서 제외된다.
- 동일 사번의 중복 이벤트는 연동 계층에서 가장 최신·유효한 상태 하나로 정규화한다.

## 해커톤 데모와 운영 전환

데모에서는 `scripts/04_generate_attendance.py`가 카드 게이트 이벤트를 모사한
`data/raw/attendance.csv`를 만들고, 대시보드의 **사원증 태깅 시뮬레이션** 버튼이
미출근 작업자를 즉시 출근으로 바꾼다. 재실행 없이 가용 인력 수와 GA 입력 풀이 갱신된다.

운영 전환 시에는 CSV 생성 부분만 다음 순서의 API 연동으로 교체한다.

1. 사내 근태 API에서 작업일·사업장 기준 당일 근태 이벤트를 읽는다.
2. HR의 사번과 `worker_id` 매핑을 적용하고, 상태 코드를 위 데이터 계약으로 정규화한다.
3. 개인정보는 화면·로그에 노출하지 않고 사번/이름 대신 내부 작업자 ID만 전달한다.
4. 출근·퇴근·공정 전환 이벤트마다 스냅샷 버전을 올리고, 변경이 있을 때만 재최적화한다.
5. 생성된 작업지시표는 MES에 `schedule_version`, 입력 근태 시각, 담당자 승인 정보와 함께 보낸다.

> 현재 저장소에는 외부 회사의 실제 HR/근태 API 자격증명이나 엔드포인트가 없다. 따라서
> API 호출을 흉내 내지 않고, 교체 가능한 CSV/어댑터 경계와 데모 카드 태깅 흐름을 구현했다.
