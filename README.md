# 유전 알고리즘 기반 선박 조립 공정 작업자 동적 배정 및 스케줄링 시스템

2026 K-조선 해커톤 참가 프로젝트 (생산 부문 AX 솔루션)
팀명: 실험준비실 (Team LabPrep)

---

## 1. 문제 정의

중·소조립 공정에서 작업자 50명을 블록별로 배정하는 조합은 완전 탐색이 불가능한 규모다.
여기에 현장에서 실제로 걸리는 제약이 네 가지 겹친다.

| 제약 | 내용 | 강제 위치 |
|---|---|---|
| 선행 공정 | 절단 → 취부 → 용접 → 사상, 그리고 블록 간 결합 순서 | 디코더의 ready 집합 |
| 자원 | 1명의 작업자는 동시간대 1개 작업에만 투입 | 작업자별 가용 시점 갱신 |
| 숙련도 | 고난도 블록의 취부·용접에 유자격 고급 인력 필수 | 인원 선발 시 우선 확보 |
| 공간 | 동일 조립장 구역 동시 진입 블록 3개 이하 | 구역 점유 예약 |

여기에 더해, 계획 공수 자체가 틀리면 어떤 스케줄러를 붙여도 지연이 연쇄된다.
숙련도 편차와 물량 특성에 따른 공수 예측 오차가 실제 지연의 상류 원인이다.

## 2. 해결 구조

```
도면/BOM ─┐
          ├─→ [공수 예측 ML]  ─→ 인원 조합별 소요시간 테이블 ─┐
실적 이력 ─┘     LightGBM + SHAP                              │
                                                              ├─→ [GA 스케줄러] ─→ 익일 작업 지시표
법령/선급규칙 ─→ [제약조건 변환] ─→ 하드 제약 파라미터 ───────┘         간트차트 · 부하율 · 준법 점검
```

세 단계를 하나의 파이프라인으로 묶었다.

1. 공수 예측: 블록 물량과 투입 인원 구성으로 실적 공수를 회귀. 표준 원단위 계산 대비 오차를 줄인다.
2. 소요시간 테이블화: GA 내부 루프에서 모델을 호출하면 수만 번 추론이 발생하므로,
   (작업 × 인원수 × 숙련도 편성) 격자를 사전 계산해 조회 비용을 O(1) 로 만든다.
3. GA 스케줄링: 4대 제약을 강제하는 디코더 위에서 우선순위·인원·편성을 진화시킨다.

## 3. 실행 결과

블록 30개(작업 120건), 작업자 50명, 개체군 300, 세대 80 기준. CPU 단일 프로세스.

| 지표 | 규칙기반 (EDD + 표준인원) | GA | 변화 |
|---|---|---|---|
| 종합 점수 | 62.9 | 74.7 | +11.8 |
| Makespan | 32.9일 | 23.7일 | -27.9% |
| 작업자 가동률 | 35.3% | 52.2% | +16.9%p |
| 부하 표준편차 기반 균형도 | 84.7% | 86.3% | +1.6%p |
| 납기 준수율 | 76.7% | 73.3% | -3.4%p |
| 유휴 시간 | 9,213h | 5,317h | -42.3% |
| 법령·선급규칙 위반 | 0건 | 0건 | - |

소요 시간 75초 (58세대에서 조기 종료). 5분 제한 안에서 수렴한다.

공수 예측 모델 (작업 1,600건, 블록 단위 그룹 분할 검증):

| | MAE | MAPE | R² |
|---|---|---|---|
| LightGBM | 6.10 | 12.2% | 0.927 |
| 표준 원단위 계산 | 8.29 | 16.4% | 0.875 |

비교군을 일부러 나쁘게 잡으면 개선폭이 부풀려진다. 비교군은 현장에서 실제로 쓰는 수준의
규칙(납기 임박 순 착수 + 공정별 표준 인원)으로 구현했다.

종합 점수의 분모는 도달 불가능한 이론 하한이 아니라 표준 인원 기준 임계경로다.
자원 경합을 무시한 하한을 쓰면 점수가 실제보다 낮게 나오고, 반대로 비교군을 분모로 쓰면
점수가 부풀려진다. 두 값 모두 `score.json` 에 함께 기록된다.

## 4. 설계상의 선택

### 랜덤키 인코딩

염색체는 순열이 아니라 세 개의 벡터다.

```
priority[J]  작업 우선순위 랜덤키 (0~1)
crew[J]      작업별 투입 인원 수
mix[J]       숙련도 편성 성향 (원가절감형 / 균형 / 숙련집중형)
```

디코더가 "선행 공정이 끝나 착수 가능한 작업" 중에서만 우선순위를 참조하므로,
어떤 난수 벡터를 넣어도 실행 가능한 스케줄이 나온다. 교차·돌연변이 후 복구 연산이
필요 없고, 제약을 만족하는 초기 세대를 검사 없이 즉시 생성할 수 있다.
`tests/test_constraints.py` 의 `test_random_population_is_always_feasible` 이 이를 검증한다.

### 법령 처리 방식

법령 원문을 모델이 해석해 스케줄을 만드는 구조가 아니다. 조항을 정량 파라미터로 1회
환산해 `config/rules.yaml` 에 기록하고, 최적화 엔진은 그 파라미터만 하드 제약으로 소비한다.
판정이 재현되고, 위반이 나오면 어느 조항 때문인지 ID로 역추적된다.

| ID | 근거 | 파라미터 |
|---|---|---|
| LAW-WORK-001/002 | 근로기준법 제50조·제53조 | 1일 가동 8+4시간 |
| LAW-SAFE-002 | 산업안전보건기준에 관한 규칙 제38조 | 중량물 최소 인원 2명 |
| CLASS-WELD-001/002 | 한국선급 선급 및 강선규칙 제2편 | 유자격 용접사, 고급 인력 1명 이상 |
| YARD-SPACE-001 | 조립장 운영기준 | 구역당 동시 진입 3개 |

### 시간 축

내부 시간 단위는 가동 분(working minute)이다. 야간·휴게 시간을 축에서 압축해 두고
간트차트를 그릴 때만 벽시계 시각으로 되돌린다. 근로시간 제약이 시간 축 자체에
내장되므로 별도 검사 없이 지켜진다.

### 데이터

조선소 실적 데이터는 대외비다. 난수로 숫자만 뽑는 대신, 공수 산출식을 코드에 명시하고
그 위에 로그정규 잡음과 숙련도 편차를 얹었다.

```
표준공수 = [용접장 × 원단위 × (각장/기준각장)^1.6 + 부재수 × 취부원단위 + 중량 × 취급원단위]
           × (1 + 곡면계수 × 곡면비율) × 선종난이도
소요시간 = 공수 × 숙련도계수 / (인원 × 병렬효율),   병렬효율 = 1 - 0.08 × (인원-1)
```

`src/knowledge/drawing_spec.py` 가 CAD/BOM 추출물을 같은 스키마로 정규화하므로,
실데이터가 확보되면 입력 경로만 교체하면 된다.

## 5. 실행 방법

```bash
pip install -r requirements.txt

python scripts/01_generate_data.py      # 합성 데이터 생성
python scripts/02_train_model.py        # 공수 예측 모델 학습
python scripts/03_run_scheduler.py      # GA 스케줄링 + 결과 CSV 출력

streamlit run app/streamlit_app.py      # 대시보드
pytest -q                               # 제약 조건 검증 (9건)
```

주요 옵션:

```bash
python scripts/01_generate_data.py --blocks 400
python scripts/03_run_scheduler.py --blocks 30 --generations 80 --pop 300
```

모든 파라미터는 `config/config.yaml` 한 곳에서 조정한다.

## 8. 한계

- 합성 데이터로 학습했으므로 예측 정확도 수치는 실데이터에서 재검증이 필요하다.
- 작업 중단·재개(preemption)를 다루지 않는다. 착수한 작업은 완료까지 이어진다.
- 구역 점유는 블록 예상 체류시간으로 선예약한 뒤 완료 시점에 갱신하는 근사다.
- 설비(크레인, 용접기) 제약은 파라미터로만 정의했고 스케줄러에 미반영이다.
